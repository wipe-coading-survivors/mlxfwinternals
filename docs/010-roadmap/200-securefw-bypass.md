# 200-securefw-bypass

**Статус:** seed
**Цель:** Обход secure-fw/Secure-Boot-ограничений на поколениях, где
самоподпись не работает (CX-6 Dx GA SECURED — boot root-of-trust вне
flash; CX-7 prod — per-burn шифрование), и выжимание возможностей чипа
поверх открытого корпуса 190. Три дуги: **(A)** CX-7 pre-release corpus
+ boot2-формат, **(B)** boot-window — исполнение кода до завершения
проверки подписи (TOCTOU), **(C)** VPD/secure-state — источник
secure-самоописания карты.
**Критерии закрытия:** по таблице «Критерии готовности» в конце тела.

(B — кандидат-путь рута на GA SECURED), `docs/010-roadmap/190-serdes-decomp.md`

## ROADMAP-SecureFW-Bypass

### Стимул (2026-11-12..14)

Гипотезы для проверки:

1. **Анлок CX-6 через VPD**: FNP + прошивка с анлоком служебного сектора
   через flint_oem + перезапись VPD → карта «думает», что она non-secure.
2. **Баг pre-verify exec** (деталей нет): в прошивках CX-7 есть баг,
   позволяющий выполнить произвольный код **до того, как проверка
   подписи закончится** (окно ~140 инструкций). Гипотеза
   владельца: присуще и предыдущим поколениям.
3. **Предрелизные открытые прошивки CX-7** — в refs (§ «Арка A»):
   промышленные дистрибутивы зашифрованы (док 051), предрелиз —
   единственный открытый plaintext-материал CX-7-контента.

Наблюдение владельца (2026-11-14, live-пробы): VPD читается `mstvpd <BDF>`
на CX-3, CX-4, CX-4 Lx и CX-7 — на CX-5/6 нет. **Обратная корреляция с
MAIN-строками**: поколения без VPD-механики в MAIN_CODE (CX-3/4/4Lx)
читаются; поколения с ней (CX-5/6/6Dx/6Lx) — нет; CX-7 (строк нет, флеш
пуст) — читается. Гипотеза-кандидат: CX-5/6 — VPD сервируется FW (путь
опосредован main-FW и гейтится), остальные — напрямую (флеш/dev-область/
EEPROM/ROM-домен). Примеры (владелец): CX-7 CX71143DMC-CDBE_FB —
V0=`PCIeGen4 x16`, UUID в V3, RV=0xa6; CX-4 HPE EDR — **V4 = MAC-адрес карты (значение machine-local — не
фиксируется)**, V0=`PCIe EDR x16 25W`, VA=`HP:V2=MFG:V4=MAC:V5=PCAR`
(структурная карта полей) → VPD несёт identity + капабилити, не только
описание. Секция 0xE3 VPD_R0 содержательно никогда не разбиралась
(CX-4/4Lx: size=0, addr=EOF 0xFF8140 — где реальные данные и кто их
пишет/читает — open). `mstflint hw query` подтверждён live на CX-7
(`Flash0.WriteProtected Disabled`).

### Свежие факты-входы (замеры 2026-11-14, не переисследовать)

- **VPD-строки** (`PCIeGen`/`CSKU=`/`MLX:MN`) в MAIN_CODE (0x03) по
  корпусу: cx4=0, cx4lx=0, **cx5=59, cx6=15, cx6dx=36, cx6lx=3** файлов
  (все — секция 03); CX-7 предрелизы — 0 по всему образу, VPD_R0
  (DTOC @0x1ff8140) стёрт → три механизма по поколениям: FS3 dev-блок →
  MAIN-механика CX-5/6 → вне-флеша на CX-7.
- **Предрелизы CX-7** (`refs/fw/cx-7/dumps/cx7_firmware_dumps/`):
  28.33.0751 (MCX713106AC-VEA, PSID MT_0000000841; +full_query/hw_query/
  ini; query: Life cycle PRODUCTION, SB Capable: Disabled, Encryption:
  Disabled) и 28.33.0800.bin (md5 `828b3ce6…`). Все секции открыты:
  0x0f FS4_BOOT3_CODE (0x2590/0x6a20), **0x14 APU_KERNEL 0x581A0**
  (новый код-домен), CCIR 0x0D/0x0E с маркерами `ztr_rttcc` (2/7
  вхождений — ид 190/арка-B extends на CX-7), 0x0C=0xE90 (=дистрибутив;
  прогрессия-Gen-маркер док 130 §5.3 сломана), boot2 plaintext
  (DW0=`0x20400040` — контейнер формата CX-6Dx), boot_record 0751 =
  init-таблица CX-5/6-стиля (≠ prod opaque 0x3f4). Подробнее — док 051 §9.
- **mstflint-гейты**: `set_vpd` — OSS, не гейтован (`flint/subcommands.cpp:6585`,
  регистрация `cmd_line_parser.cpp:98`; на живой карте с `-ocr`);
  `hw set` — `#ifdef EXTERNAL` (`subcommands.cpp:7289`), EXTERNAL вводится
  только SDK-режимом сборки (`configure.ac:608`) → **non-external билд из
  refs = функциональный эквивалент flint_oem для hw set/query**; WP =
  SR1/SR2 BP/TB SPI-NOR (журнал 2026-09-28), `secure_fw` среди hw set
  атрибутов НЕТ — write-protect и secure-state разные слои.
- **Кросс-флеш CX-7 параллельных сессий** (`crossflash-mt1030`,
  `fb-28.34.4000`, `multiburn`): не дал результата (владелец,
  2026-11-14) — не повторять вслепую.

### Якоря из прошлых циклов (не переисследовать)

- **Boot root-of-trust CX-6Dx вне flash** (HB-b, confound-free): VPI-патч
  на GA SECURED — no-boot при всех классах подписи, вкл. наш 0xA4+X.509
  (циклы cx6dx-securefw/introspection; 150 §C3) → самоподпись на Dx
  закрыта, нужен иной путь (= арка B).
- **Boot-крипто-модель CX-7** (051 §8, цикл cx7-boot-crypto): SB-v2-окно
  (ROM → boot_record/boot2/hashes-table), два класса keystream
  (per-burn/build), 4B AUTH-TAG/строка у cache_line_crc-секций,
  оракулы (ITOC-пара pt↔ct, CoRIM-дайджесты, hashes-table). Заявка «окно
  ~140 инструкций» ложится в стадии 0–2 модели (ROM→boot2→ITOC) — арка B
  формализует и ищет сайт.
- **Открытый постулат** (110-signing/065): «где ROM берёт secure-решение —
  образ/чип/данные — не разрешено». Рецепт-заявка = гипотеза
  «источник = VPD/служебный сектор»; напряжение с 030 §3 («якорь вне
  flash» для CX-6Dx) → кандидат-разрешение: двухслойная модель
  (lifecycle-OTP неизменен; runtime-политика/MGIR.secured — из данных).
- **flint_oem/hw set RE** — журнал 2026-09-28 (полная цепочка до
  SPI-опкодов); **read-политики** — 050-spi-read-policy (MCDA/secure);
  **CCIR = RoCE CC** — 190 арка B; **корпус 190-A** — субстрат всех
  офлайн-поисков (54 образа, траст-слой).

### Арка A — CX-7 pre-release corpus + boot2 — [ ]

- [x] A1. Эрратум/аддендум к док 051 (предрелизы открыты; boot2
      plaintext; boot_record v1-style; смягчение §7.1/§8.4; 0x0C=0xE90) —
      §9, этим же коммитом.
- [x] A2. Расширение корпуса (190-A) предрелизами 0751/0800: манифест
      (md5-пины), провизорный профиль cx7 (recount), классификация
      доменов 0x0f BOOT3 / 0x14 APU_KERNEL (PriorDisagreement-гейт);
      дифф 0751↔0800 (байтовый → дизасм-дифф расхождений).
      — Сделано (task-01..03): T3 + профиль (MAIN 0.875), домены
      0x0f=iRISC / 0x14=RISC-V data (040 §1; override не потребовался);
      дифф 12/17/0: MAIN 90.19% (общих функций 249/12384 — пересборка),
      CCIR/boot_record почти стабильны.
- [x] A3. **boot2-формат**: идентификация на plaintext-материале
      (линза задачи-2 цикла cx7-boot-crypto: компрессия-гипотезы
      отвергнуты на fb-шифротексте — пере-проверить; iRISC? другой ISA?
      кросс-дифф с CX-6Dx boot2 plaintext).
      — Вердикт (task-04): plaintext iRISC в Carmel-контейнере
      (CRC16-валид, known-form 98.6/98.7%, не компрессия/RISC-V/ARM;
      с CX-6Dx общий только контейнер) — 051 §9.
- [x] A4. boot_record: разбор пары «0751 init-таблица vs prod opaque
      0x3f4» (формат init-таблицы читался журналом 2026-09-20 на CX-5/6);
      что превратило её в CX7-blob к продакшену.
      — Сделано (task-05): extent 0x3f4 = getBootRecordSize(CX7), дифф
      11 B (2 CR-init SKU-строфа + счётчик + tag16-трейлер), SB-V2-layout
      уже в 28.33 (hashes-table plaintext-карта); переход — гипотезы
      H1–H5, дискриминатор 28.34+ (051 §9).
- Правила: предрелизы — офлайн-материал; burn предрелиза на живую CX-7 —
  отдельное решение владельца; свежие линейки (28.50/28.35/28.36) —
  diff-witness'ы, не база.

### Арка B — boot-window: исполнение до завершения verify — [ ]

- [ ] B1. Формализация заявки в проверяемые гипотезы: где окно (ROM-прыжок
      в boot2 до его верификации; boot2→BOOT3/ITOC handoff; вход
      IRON_PREP до хеш-проверки; построчные 4B AUTH-TAG cache_line_crc —
      «первые N инструкций строки до проверки тега»); что «140
      инструкций» — масштаб окна.
- [ ] B2. Офлайн-поиск сайта: предрелизы CX-7 (открытый бут-материал) +
      корпус CX-6Dx/CX-5 (переносимость заявки на старшие поколения);
      модель 051 §8.2 как карта стадий.
- [ ] B3. При находке — спека live-эксперимента (owner-gated; FNP-класс,
      субагент). Критерий ценности: путь рута на GA SECURED без ключей
      (unblock 150).
- При ненахождении офлайн — задокументированная граница (boot2/fuse
  вне образа), опция ROM-dump (`docs/850-howto/130-rom-dump.md`).

### Арка C — VPD/secure-state — [ ]

- [ ] C1. Карта VPD-механики по поколениям: FS3 dev-блок — **разбор
      0xE3 VPD_R0** (где реальные данные при size=0/addr=EOF, кто
      пишет/читает, связь с identity VPD-полей: MAC в V4 и т.п.);
      MAIN-строки CX-5/6 — **build vs parse** (xref от строк по траст-слою
      корпуса: FW генерит VPD хосту или бут читает VPD-политику?);
      CX-7 — вне флеша (config-space VPD capability / cr-space /
      ROM-домен). Проверить гипотезу обратной корреляции: mstvpd
      CX-3/4/4Lx/7 (прямой путь) vs CX-5/6 (FW-опосредованный, гейт).
- [ ] C2. Дифф VPD-контента secure↔non-secure одноплатных пар (дампы/наши
      карты) — есть ли security-несущие поля (ID-строка «…and Secure
      Boot»?).
- [ ] C3. Инструменты: non-external mstflint-билд (`hw set`; sibling
      `../mstflint-container`); OSS `set_vpd` (проверить на образе);
      mlxfwutil — патч VPD_R0 в образе (CRC-обвязка).
- [ ] C4. Live read-only пробы (субагент): mstvpd/MGIR-матрица по нашим
      картам (CX-3/5/6/7), CR-space VPD-cap; закрыть постулат 065 или
      сузить.
- [ ] C5. Проверка гипотезы анлока (FNP + анлок служебного сектора +
      перезапись VPD на CX-6) — **owner-gated, отдельная спека**; вход —
      C1–C4.
- Оговорка: «VPD-перезапись снимает secure» — гипотеза, не факт;
  верификация обязательна (MGIR до/после, контроль lifecycle).

### Правила

- Live-HW — только субагент + журнал (AGENTS.md); любой burn/FNP —
  решение владельца; предрелизные образы в burn не идут без отдельного
  решения.
- Порядок: A (дешёвый офлайн, разблокирует материал B) → B → C; C3 не
  блокируется ничем (можно параллельно).
- Новые номерные доки — docs-num-ask-first; канон-факты — в 051/065/030
  по мере закрытия дуг.

### Критерии готовности

| # | Критерий | Арка |
|---|---|---|
| I | Предрелизы в корпусе (манифест/профили/домены), дифф 0751↔0800; эрратум 051 влит | A |
| II | boot2-формат идентифицирован (или задокументированная непрозрачность с контрольными альтернативами); boot_record-пара разобрана | A |
| III | Boot-window: вердикт «сайт найден (где/как эксплуатируем)» или «офлайн-невидим (домен-локализация)» по стандарту «не найдено ≠ опровергнуто» | B |
| IV | VPD-механика по поколениям задокументирована (build/parse, где живёт, кто читает); постулат 065 закрыт или сужен с прямыми уликами | C |
| V | Гипотеза анлока: воспроизведена или опровергнута позитивным доказательством (какой слой держит secure-state) | C |
