# 140-irisc-vm

**Статус:** utopia
**Цель:** виртуальная машина, в которую загружается образ прошивки (FS2/FS3/FS4)
и он исполняется на модели внутреннего процессора карты — для отладки наших
правок образов и наблюдения за поведением прошивки без живого железа;
кандидат на VM-отладку iRISC. Долгосрочная: идёт параллельно с другими
треками, не блокирует их.
**Критерии закрытия:** загружаем образ (хоть и в первую очередь
оригинальный, known-good) в эмулятор и по трассу/логу видим поведение
управляющего FW; оригинальный запустился — можно ковырять патченные (diff
поведения против base) — без живого железа.
**Фазы/задачи:**
- [ ] studies (артефакт — нумерованный док, например `docs/80`, номер
      уточнить, + вердикт): что исполняет FW (какой процессор/ядро на
      поколение), boot-путь (ROM → FW), минимальный набор памяти/периферии
      для запуска, QEMU vs свой эмулятор, риски
- [ ] studies (потенциальные блокеры): поведение управляющего интерфейса на
      крайних SKU — CX-2 (IB-only, поведение «отказ Eth» 1-в-1 с нашим
      IB-гейтом; карта есть в наличии) и CX-6 Dx (EN-only, Facebook-образ):
      от каких конфиг-секций решения зависят (VPI/PSID/HW_*_CFG/…),
      отделить SKU/конфиг-гейт от трансиверного гейта: проблема CX-4Lx/CX-5
      (SFP28) — вероятно трансиверы, не репортящие SDR/QDR/FDR; CX-2 (QSFP+)
      и CX-6 Dx (QSFP28) обе не SFP+/SFP28, и QSFP+/QSFP28-трансиверы (по
      крайней мере) совместимы и с Eth, и с IB
- [ ] тестбенд: минимальная модель + загрузка первой секции (ROM_CODE/
      MAIN_CODE) + первый трасс исполнения; старшее поколение первым
      (кандидат CX-2 FS2 — чем старше, тем проще)
- [ ] отладка: GDB/трейс/брейкпоинты, логирование взаимодействий с
      эмулированным «железом»
- [ ] первый use-case: наблюдать эффект наших правок образа (напр., VPI /
      IB-гейт) в эмуляторе — diff поведения против base-образа
**Семёна:** ROADMAP-секция «Эмулятор прошивки» (долгосрочная цель, поднято
2026-09-16); в roadmap-restructure.md §3 — «утопичный, с пометкой».

# Эмулятор прошивки (долгосрочная цель)

Слой: «внутренний мир» карты — внутренний процессор + память + периферия;
бинарь FW реально исполняется, отладка — GDB/трейс/брейкпоинты. Ключевое
допущение (владелец): чип = две независимые сущности — ASIC свитчинга и
управляющий интерфейс; цель эмулятора — управляющий интерфейс, принимающий
решения (secure_fw/secure_boot, принятие/отказ трансиверов, режимы портов).
