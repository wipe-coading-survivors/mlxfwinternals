## 1. Лестница гипотез (спека §4.4)

Семантика: «не найдено» ≠ «опровергнуто»; класс улик — по §4.2 спеки
(первичная = same-silicon/live/прямой офлайн; вторичная = непрямая/
кросс-семейная; confounded = Gen×SerDes-генерация).

| Гипотеза | Вердикт | Класс улики | Источник | Базис |
|---|---|---|---|---|
| **H-A1** (dedicated: дизъюнктные банки) | **REFUTED** | первичная | C4 §3–§4, §7 | банки 0x0C ⊆ 0x0A строго во всех 6 семьях (CX-4gen: 100% банков и 100% записей 0x0C в общих); контроли K1/K2 = 0 ложных пересечений |
| **H-A2** (два экземпляра одного IP) | **OPEN, ослаблена** (not supported на lane-уровне, не опровергнута) | первичная (структурные негативы + кросс-блоковые позитивы, CX-5) | task-02 §Verdicts; C5 = task-06 §Вердикты | нет дублированных stride-спектров; единый lane-источник (port-struct[0]) кормит унаследованные/Gen4-EQ/CX-5-only блоки; для фальсификации не хватает доменной атрибуции writer-семей (статика — dead-end) и live lane-ID (C5 закрыл только пассивный путь, §5) |
| **H-B** (shared + ручка в данных) | **SUPPORTED, накапливается** (структурная часть; shared-часть на MT27710 не закрыта — §2) | первичная (структура данных/окна), вторичная (семантика ручки — наследована из док 130 §10.3) | task-02 F1/F5, task-01, task-04, C4 | per-lane пространство с config-window-гейтингом; код SKU-инвариантен → провижининг в слое данных; писатели window вне образа; SKU-поле-кандидаты — док 190 |
| **H-C** (per-rate: 14 ГБод-конфиги вырезаны в Lx) | **REFUTED** | первичная | task-03 §«H-C тест» | 0x0B: cx4 ≡ cx4lx байт-в-байт (0 из 11392); 0x0A: 1 байт из 39200 (слот 1351, см. §6/док 075 §5) |

## 2. Главный вердикт: shared/dedicated per-семья

Стоп-критерий §5 спеки: ≥2 независимых прямых первичных улик — или
честное open с исчерпанным списком слоёв.

- **MT27800 (CX-5): SHARED — 2 независимые прямые первичные**: (1) C4
  bank-subset (26 общих пар, 30% записей 0x0C, Gen4-материал 0x79cc в
  общих банках); (2) task-02 F5 — lane-ID непрерывность: один lane-байт
  port-struct[0] адресует 0x9d (lane<<13) и 0x9b (lane<<11) с
  read-modify-write через блоки разных поколений (fn 0x786988).
- **MT27710 (CX-4 Lx): OPEN** — 1 прямая первичная (C4: bank-subset;
  0x0C Lx побайтово == CX-4). Недостающие классы §4.2(б,в,г): доменная
  атрибуция writer-семей (статика dead-end), lane-уровень live (C5 —
  пассивный путь исчерпан, §5), конфиг-поле «PCIe-width × порт-лейаут»
  (в SKU-диффах не найдено — док 190). **Open с исчерпанным списком
  слоёв**: конфиг-слой 0x08/0x09/0x11/0x12 (task-01), весь iRISC-код
  образа (task-02 lane-scan + task-04 allcode-sweep), µкод/данные
  0x0A/0x0B/0x0C (C4 + task-03), boot-секции статически (task-04:
  IRON_PREP экзонирован, window-писателей в образе нет), пассивные
  CR-чтения живой карты (C5). Где недостающее: sequenced selector-доступ
  / boot-dump / VFIO-mlxdirect (§5), ROM-dump стадия 2 (owner-gated,
  `docs/850-howto/130-rom-dump.md`), доменная атрибуция writer-семей
  (0x78f04c/0x78f110 vs speed-change switch — глубокое RE, дорого).
- **MT27700 (CX-4): как Lx** — 1 прямая первичная (C4; 0x0C совпадает с
  Lx побайтово), open.

Приоритетная гипотеза — H-B (shared + ручка в данных), поддержана
накопительно; H-A1 опровергнута; H-A2 ослаблена.

## 3. Локализация механизма роли ланов

- **Роль-структура: port-struct** (task-02 F6, первичная): все per-lane
  utility-функции берут указатель порт-структуры; byte[0] = SerDes lane
  ID, byte[1] = вторичный id (`ld.b r4,r23,0x0/0x1`) — эта запись и есть
  связь SerDes↔port-role. Билдер (кто назначает lane-ID портам) в образе
  не найден → pre-image (ROM/loader); кандидаты role_table — task-02
  п.3 «исследовано и исключено».
- **Per-lane адресация** (якоря): LX/CX-4 quad-идиома
  `(lane&3)<<12 + (lane>>2)<<15` (квады по 0x1000, квад-шаг 0x8000;
  LX dc 0x781330..0x7813a8, базы 0x8c0ddf/0x8c0cff); CX-5 fn 0x786988
  (в speed-change switch 0x786040–0x786c00): 0x9d8c20/0x9d8e20+lane<<13
  (чтения), 0x9d8cc0/0x9d8ec0+lane<<13 (записи), 0x9b821f+lane<<11;
  CX-5-only 0x90-блок — lane<<12 (0x90095e/0x9000bf). CR 0x28 =
  write-селектор/строб PHY-regfile. Stride-спектр эволюционирует
  аддитивно: cx5 сохраняет {9..12,15}, добавляет 13 (Gen4-EQ) и 5 —
  блок-ренейминг поколений, см. док 130 §10.4.
- **Гейтинг данными**: per-lane SerDes-операции читают config-window
  слоты перед записями — CX-5 callee 0x786c0c читает 0x9b8380+lane<<11
  (регистр, пишемый независимыми fn 0x78f04c/0x78f110) и гейтится на
  RAM[0x3758]; LX speed-4 ветка — RAM[0x3ab9]>>4 (док 130 §10 p.1).
  Окна: LX RAM[0x3a9f..0x3b2c], CX-5 RAM[0x3753..0x379c].
- **Код SKU-инвариантен** (task-02 F1: идентичные hit-мультисеты
  cx4×7/cx4lx×7/cx5×9 SKU), µкод-секции SKU-инвариантны (C4 §1) →
  провижининг целиком в слое данных (поле-кандидаты — док 190).
- **Boot-домен** (task-04, первичная): window_write = 0 по всем
  iRISC-секциям 54 образов → писатель window (канал данных) вне образа
  (ROM/FlexBoot/loader); **IRON_PREP (0x05) экзонирован статически**:
  0 window-записей, 0 когерентных flash-адресов конфигов, самозамкнутый
  call-graph (конфаунды задокументированы: слепота к вычисляемым базам,
  числовой перекос cx4-gen flash-канала). Потребление 0x08/0x09/0x11
  iRISC-кодом не локализовано (open: flash-controller regfile /
  loader-копия / pre-image ROM). Локализация роли — **доменная**:
  данные+окно (образ) → писатель/аллокатор (pre-image).

## 4. Эррата: prelude-район и REL24

Журнал `2026-09-20-fw-iron-boot-chain` описывал «prelude-район ниже
load-базы» (~25 call-сайтов, 110KB вне образа) — **wraparound-артефакт**
shifted-view проекта Ghidra (iron05e): отрицательные PC-relative цели в
shifted-координатах рендерятся как 0xfffeXXXX и неверно резолвились
правилом «load_base + signed32». **Канон: REL24 = PC + rel24×4**
(`scripts/irisc/iRISC.slaspec:155`; live-факт v3-детура —
`docs/250-re/120-irisc/025-boot-injection.md` §2). Перепроверка (task-04
F2, первичная): 0x05 call-целей ниже param0 — 0 во всех образах; все
1376 entry-tree целей в секции; SP-init stub cx6dx — ровно там, где
«0xfffe42e8» ложится при PC-relative каноне.

## 5. C5: live-пробы (исполнены 2026-11-12, owner-approved)

Read-only (mstmcra-чтения/lspci/mstflint q+dc), 0 записей, status-map
delta none на всех 4 картах (CX-5 Ex Gen4 81:00.0, CX-5 Gen3 01:00.0,
CX-4 Lx c1:00.0, CX-4 42:00.0). Полные таблицы — task-06 журнал +
task-6-report. Вердикты:

1. **Per-lane structure: NOT OBSERVED пассивно** — первичная
   **калиброванная негативная** (валидный результат, не провал): все
   per-lane SerDes-адреса (0x9d/0x9b/0x90 на CX-5; 0x8c quad+linear на
   LX/CX-4) читаются как uniform 0x00000000; в SerDes-регионе нет
   echo-семантики (пробы отсутствующих блоков 0x8a0000/0x8d0000/0x970000
   = тот же 0) → value-дискриминация mapped/unmapped невозможна.
   Согласуется со статикой: доступ к PHY-regfile — через CR 0x28
   selector+strobe последовательность (док 130 §10 p.3), не пассивная
   CR-страница. «Не найдено» ≠ «опровергнуто»: статические улики
   (единый lane-источник, task-02 F5) не затронуты.
2. **H-A2: остаётся weakened-not-refuted** — пер-лановых значений нет →
   4+4 vs 8+8 сплит не наблюдаем этим инструментом. Закрытие: sequenced
   selector-доступ (запрещён read-only констрейнтом), boot-domain dump
   или VFIO/driverless путь (mlxdirect).
3. **Window-slot метод-артефакт: ПОДТВЕРЖДЁН репродукцией** — CX-5 обе
   карты: окно 0x4dd4c..0x4de70 = 74/74 uniform `0x00010000`, включая
   новый F5-гейт-слот RAM[0x3758]→0x4dd60 (заливка; пассивно слот не
   отличим); кросс-FW (4030↔8008) и кросс-Gen (3↔4) стабильно; транзиенты
   одиночны и 8×-нестабильны (0x4de64=0xc). LX: окно 0x4ea7c..0x4ecb0 =
   142/142 mapped-zeros (точный репроук §10.2, транзиент 2026-10-24 не
   наблюдается). Per-speed слоты пассивно не наблюдаемы; семантика
   остаётся производной от статики.
4. Метод-калибровка для будущих проб: echo-дискриминатор
   (unmapped → A>>2) работает только в window-регионе (0x4xxxx/0x66xxx;
   0x66570→0x1995c = unmapped-echo, 0x66280 = mapped-zero); живой
   контроль 0xf0014 валиден на всех картах (0x20d/0x20d/0x20b/0x209).

Итог по MT27710: passive CR-читения как инструмент исчерпаны; остаток
OPEN сузился (см. §2).

## 6. Вход для арки D (слои отсечения негативов)

### Gen4 (PCIe, док 130 §10.3)

Отсекающий слой: **отсутствующий EQ/µкод-слой Gen4 на CX-4gen** — не
per-rate константы и не «Gen3-only силикон» как данность:

- task-02 F2 (первичная, scan-независимый set2-ценз): cx4/cx4lx
  материализуют только блоки 0x8c/0x8e/0x8f, ноль констант 0x90–0x9f —
  Gen4-EQ регистры отсутствуют даже как адреса; cx5 — полный набор.
- C4: Gen4-EQ-материал в 0x0C появляется только у CX-5 (0x79cc-блок
  0x400..0x480); 0x0C CX-4gen — Gen3-семейный.
- task-03: H-C опровергнута → per-rate константы на Lx присутствуют.
- task-04: конфиг-канал в образе окон не пишет (внешний писатель) —
  конфиг-патч EQ-слой не создаёт.

Для D: реванш Gen4 на MT27710 = перенос EQ-слоя (код 0x9d-обвязки +
Gen4-материал 0x0C) — уже не конфиг-патч; без реванша негатив
закрепляется слоем «отсутствующий Gen4-EQ/µкод-слой при присутствующих
per-rate данных» — в точности предсказание H-B.

### FDR/56G (56-100g, an-fsm)

Отсекающий слой-кандидат: **per-lane физический бюджет + единственный
µкод-дифференциал** — не данные, не конфиг-рычаги:

- task-03 (первичная): 14 ГБод-конфиги на Lx присутствуют —
  «вырезанных конфигов» нет.
- Конфиг-рычаги исчерпаны (an-fsm, якорь); кристалл-факт: 4 пары TX/RX,
  25G держат ≤2 лана.
- **Лид для D**: единственный µкод-дифференциал CX-4↔CX-4Lx — слот 1351
  0x0A (wr6165 p=27 blk=3 reg=9cc addr=0x820, val 0→1) — цель в списке
  9 точных общих (b,c)-пар 0x0A∩0x0C (C4 §3; здесь — пара (0x39cc,
  0x0820)), т.е. в регистре, куда пишут оба µкода. Гипотеза (не факт):
  бит-гейт; дифференциальная мишень для D-спеки.
- task-04: провижининг window — внешний (ROM/loader) → часть ручки может
  жить в pre-image, недостижима конфиг-патчем образа.

Для D: FDR-негатив закрепляется слоем «per-lane бюджет/биннинг ланов при
присутствующих per-rate данных» (H-D-совместимо); альтернатива —
дифференциальный эксперимент по слоту 1351 (отдельная burn-спека, по
решению владельца).

## 7. Исследовано и исключено (синтез уровня цикла)

1. **Dedicated-макрос с собственными банками** — опровергнуто (C4,
   первичная, все 6 семей).
2. **«Два экземпляра одного IP» как объяснение overlap** — не
   поддержано на lane-уровне (task-02, первичная); не опровергнуто
   окончательно (доменная атрибуция; C5 пассивно закрыт).
3. **Per-rate вырезание конфигов в Lx-SKU (0x0A/0x0B)** — опровергнуто
   (task-03, первичная, байтовые диффы).
4. **Роль/аллокация ланов внутри образа** — не найдено: билдер
   port-struct и таблицы «порт→SerDes-лы» в образе отсутствуют (task-02
   + task-04, первичные негативы с задокументированными конфаундами).
5. **IRON_PREP как парсер конфигов/писатель window** — экзонирован
   статически (task-04, первичные негативы; см. §3).
6. **«Prelude-район ниже load-базы» (журнал 2026-09-20)** — опровергнут
   как артефакт shifted-view (task-04; канон REL24 — §4).
7. **Конфиг-поле «PCIe-width × порт-лейаут»** — не найдено в SKU-диффах
   (task-01, первичная по диффам); 0x08-кандидаты понижены до secondary
   (дрейф 22.47↔22.50 в same-PSID контроле) — док 190.
8. **0x0B как адресная/индексная таблица на 0x0A** — опровергнуто в
   пределах прямых интерпретаций (C4 §6 + task-03 index_alignment = 0);
   константы CX-6-gen не в immediate-полях и не в других секциях;
   ROM-движок — open. Формат — док 075.
9. **Пассивные CR-чтения как инструмент lane-ID/role калибровки** —
   исключено (C5, echo-калиброванный негатив, первичная) — §5.

## 8. Арка B: A16 — позитивный контроль (2026-11-12)

> Источник: цикл serdes-arc-b (`docs/superpowers/reports/serdes-arc-b.md`
> — полная цепочка улик; журналы `docs/superpowers/journal/
> 2026-11-12-serdes-arc-b-task-0{1,2,3}.md`; инструменты
> `scripts/probes/serdes-prov/a16_diff.py`, `ccir_scan.py`).

- **H-B1 подтверждена продуктово (CX-6)**: роль SerDes-ланов A16
  (PCIe-свич на CX-6-кремнии, PG171, билд-линия 20.43.8002) =
  config/ini-слой: A16-side `pcie_switch_en`, `pcie_links_width`,
  `hide_hca`, `no_port_device`, EQ/preset-ручки; NIC-side
  `module.num[0].m2l.{tx,rx}.lane[N].serdes` — таблица
  порт→SerDes-ланID в ini/nvconfig (хвост C1 заострён: lane-аллокация —
  данные образа, не iRISC-код); конфиг-спаны — док 190 §2.
- **Код+µкод byte-identical** exact-линейке HCA-8002 (md5 raw +
  de-clcrc, вкл. MAIN_CODE; function-level 11598/11598),
  lane-арифметика/port-struct не изменены (hit-мультисеты 611=611,
  кластеры равны): смена роли (трансиверы → PCIe) без единого байта
  кода/µкода.
- **C4 shared-evidence подтверждена позитивным контролем**: продуктовый
  свидетель ремукса SerDes→PCIe; H-B поднята до «продуктово доказана на
  CX-6» (H-A2-lane-кавиат и поколенческий кавиат CX-4gen не снимаются —
  отчёт цикла §1). CCIR (0x0D/0x0E) к SerDes-механике не относится
  (RoCE RTT-CC — док 040 §1).

## 9. Арка D: поле-карта — live-исходы реванша (2026-11-13)

> Источник: цикл serdes-arc-d (`docs/superpowers/reports/serdes-arc-d.md`
> — вердиктная таблица и улики; журналы task-01..07b). Карта
> MCX4131A-GCA (root-mellanox), база — чистый сток 1912-GCA. Здесь —
> только дополнения к карте полей; Gen4 — док 130 §10.5.

- **lcl-биты 56G/100G (№3: `0x12+0x30B`)** — прожиг повторен в новом
  окружении (owner-рулинг после T0-стопа: lcl уже жёгся в прежних
  циклах): дискриминаторы live воспроизведены (0x7b → Enabled
  0xf801f1d3 без 100G; 0xfb → 0xf8f1f1d3 с 100G; ethtool-advertised
  следует маске) — поле подтверждено как ручка advertisement-слоя;
  вердикт по линку — LAYER-CUT(AN handshake) в обоих случаях
  (50G CR2-контроль линкуется).
- **Маска IB-скоростей (источник — MAIN_CODE, не SKU-диффы; сайт — док
  190 §4)**: маска-слово прожжено и доказано live — flash-readback
  0011001f/0011003f активного банка; Enabled Link Speed **0x1f live**
  (FDR в advertisement, post-filter артефакт не возник); 0x3f →
  effective 0x1f (bit5 снят постфильтром). Маска не является гейтом
  линка (owner: стоковые карты линкуются 4xEDR без масок) — вердикт
  LAYER-CUT(AN handshake) при открытой маске, вечный config-цикл
  {0x30..0x43} без polling/linkup.
- **Слот 1351 (0x0A, addr 0x820)** — направление патча уточнено
  (арка-C «0→1» = дифф cx4→Lx; Lx-база уже 1); испытан 1→0 (CX-4-like):
  побочных эффектов нет (ETH-поверхность == базовой, PHY жив);
  верификация ниже handshake недостижима (PTYS-форс: ICMD 0x3 /
  0x7CD836 на обоих концах пары).
- **VPI-байт (поправка к IB-рецепту)**: EN-сток (VPI 0x0a @0x172af) не
  экспонирует LINK_TYPE_P1 → IB-режим недостижим на L-образах без VPI;
  рабочая сборка = VPI 0x07 + явный NV set IB (прецедент qsqp28-ib;
  NV-override ETH(2) переживает burn'ы и снимается set'ом).
- **Gen4 (PCIe)** — см. док 130 §10.5: advertisement-ручки P2a работают
  runtime; гейт — LnkCtl2 speed-vector силикона; µкод исключён.
