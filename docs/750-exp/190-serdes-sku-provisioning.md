> `docs/750-exp/180-serdes-provisioning.md` §3; прецедент field-map —
> док 130 §3.

Практический справочник: какие конфиг-поля-flash дифференцируются по SKU
при неизменном коде, что является версионным шумом, и какие поля —
кандидаты провижининга портов/ланов. Правило чтения: «не найдено» ≠
«опровергнуто» — офсет, не попавший в диффы, всё же может нести функцию.

## 1. Методика: пары и нулевые контроли

Дифф секций 0x08/0x09/0x11/0x12 (byte-span слияние; cl=1 → clcrc-unwrap;
md5-кроссчек payload) по парам корпуса:

- **P1 Lx primary**: cx4lx 14.32 GCA@1900 (1p QSFP28) ↔ ACA@1912
  (2p SFP28) — порт-тайп дискриминатор;
- **P2 CX-5 same-version SKU**: 8008/1012 ACA↔ADA (реплика ×2);
- **P3 cross-version same-PSID**: конфаундед-пары = они же контроли;
- **P4 lineage witness**: cx6dx↔cx6lx (межпоколенная, всё диффается);
- **P5 нулевые контроли**: все same-PSID пары корпуса (10) — при
  close-version дают 0 спанов в 0x08/0x09.

Ключ метода: SKU-специфичность поля = дифференцируется в P1/P2
(первичная) И не дифференцируется в same-PSID контроле (вычитание
версионного шума).

**Версионный шум** (исключать из SKU-кандидатов): `0x11+0x006..0x00f`
(build-stamp, меняется у всех кросс-версионных пар);
`0x12+0x018, +0x072…+0x07f, +0x749/+0x74d` — тот же регион у cx4lx и
cx5 (класс: первичная по нулевым контролям). 0x08/0x09 в близких
версиях стабильны; 0x11/0x12 контроль дают только с вычитанием шума.

**Ограничения метода**: пары с 16.19 (старая ветка) конфаундят всё
(SIZES-дрейф layout 0x09/0x12, 80–297 спанов) — исключены; минорный
дрейф 22.47↔22.50 (same-PSID, 0x08=55 спанов при 0x09=0) показывает,
что 0x08 не полностью версионно-стабилен.

## 2. Поле-кандидаты провижининга

| # | Поле (гипотеза) | Локация | Пара(ы) | Наблюдение | Класс |
|---|---|---|---|---|---|
| 1 | port-type/presence VPI port1 | `0x11+0x2B3` | Lx P1 − контроль | 1p QSFP28: 0x00 (port1 нет) → 2p SFP28: 0x0a (EN) | **первичная** (совпадает с анкором VPI port1 из `scripts/probes/diff_1900_1912.py`) |
| 2 | port-count byte ×2 | `0x11+0x119`, `+0x129` | Lx P1 − контроль | 01→02 и 02→04 (удвоение на 2-портовой); смежные с +0x2B3 | **первичная** (одна пара) |
| 3 | lcl ETH speed mask per-port | `0x12+0x30B`, `+0x317` | Lx P1 − контроль | port0 3b→0b; port1 00→0b (маска port1 нулевая у 1-порт) | **первичная** (ANNOT lcl[0]/lcl[1]) |
| 4 | host-mgmt per-port | `0x12+0x283`, `+0x2C5` | Lx P1 − контроль | 00→12 / 00→10 (нули у 1-порт) | **первичная** (ANNOT host-mgmt p0/p1) |
| 5 | per-port lane-rate/Gen слово | `0x09+0x86C` span4 | CX-5 ACA↔ADA @8008/@1012 | `30d4 30d4 → 3548 3548` (LE, симметрично port0/port1; ACA=25G, ADA=50G) | **первичная** (реплика ×2 версий; в same-PSID кросс-версии не диффается). Это же семейство — Gen4-tuning-поле док 130 §3 (`0x09+0x86c..f`) |
| 6 | speed/port code | `0x12+0x27B` | CX-5 ACA↔ADA @8008/@1012 | 0x0a→0x02 | **первичная** (реплика ×2) |
| 7 | HW-boot SKU-байт | `0x08+0x22` (Lx), `+0x23` (CX-5) | P1; P2×2 | Lx 02→00; CX-5 87→8f | **secondary** (одно наблюдение на семейство, офсеты не совпадают, семантика неизвестна; дрейф 0x08 у 22.47↔22.50 понижает доверие) |
| 8 | per-lane таблица (stride 0x10) | `0x12+0x2DB…+0x32D` | P4 witness cx6dx↔cx6lx | 6+ вхождений с шагом 0x10: байт 02→01, слово 0810/0820→0400 (равномерно 2:1) | **confounded/witness** (межпоколенная пара; структурный stride-паттерн — улика на lane-level провижининг) |
| 9 | mask-поля width | `0x09+0xFF0…0x1058` | P1 | 0fff/1fff ↔ 1007…100a/0020/1002 (маски → коды портов) | **первичная** (только P1; семантика портов-масок — гипотеза) |
| 10 | Gen4 max-speed / per-pcore/link / per-port caps (роль A16) | `0x08+0x023`, `+0x0af`, `+0x126…+0x1d2`, `+0x276` (63 Б) | арка B: A16 ↔ NIC 8002 (1014/8016 — цензор) | 63/63 differing bytes = nic_consensus трёх NIC-линеек | **первичная** (A16-специфично при согласии всех 3 NIC; ini-имён нет) |
| 11 | per-lane EQ-кластер (роль A16) | `0x09+0xe9d…+0xec7`, `+0x1030` (39 Б) | арка B | 39/39 = nic_consensus | **первичная** (per-lane EQ-регион) |
| 12 | subsystem_id / port-count регион (роль A16) | `0x11+0x03c`, `+0x06e/70/72`, `+0x120…+0x131` (15 Б) | арка B | 15 consensus / 72 disagree (шум вычтен цензором) | **первичная** |
| 13 | обнуление lcl ETH speed masks (роль A16) | `0x12+0x2ae…+0x2af` (+0x023/+0xe3/+0x223/+0x264/+0x267; 7 Б) | арка B | 7 consensus / 10 disagree | **первичная** (ср. №3 — lcl ETH speed mask) |
| 14 | lane→SerDes таблица (m2l) | ini `0x30`: `module.num[0].m2l.{tx,rx}.lane[N].serdes` | арка B: A16 ↔ NIC | NIC-side таблица порт→SerDes-ланID в ini/nvconfig; у A16 отсутствует целиком (с сетевым набором) | **первичная** (хвост C1 заострён: lane-аллокация — ini-слой, не iRISC-код) |

Исключено из кандидатов: `0x11+0x2AF` (VPI port0) — не дифференцируется
ни в одной паре (port0 EN у всех); как port-count поле исключено, как
port-type — вторичная улика (живое измерение 56G-цикла).

Дополнение арки B (2026-11-12): строки 10–14 — дифф A16 (PG171
PCIe-свич ↔ три NIC-линейки 20.43); метод — консенсус трёх NIC-линеек
(nic_consensus = все NIC равны, A16 отклоняется; версионный шум
nic_disagree вычтен). Полные таблицы и цепочка улик —
`docs/superpowers/reports/serdes-arc-b.md`.

## 3. Практические следствия для патчей

- **SKU-стабильность внутри PSID**: 0x08/0x09 — 0 спанов у всех
  близко-версионных same-PSID пар → патчи 0x09-полей (напр. +0x86C
  lane-rate слово) не конфликтуют с версионным дрейфом; 0x11/0x12 —
  только вне шумовых регионов (§1).
- **Поля «PCIe-width × порт-лейаут» (искомые аркой C) в SKU-диффах не
  найдено** (первичная по диффам) — corroborates локализацию роли ланов
  вне конфиг-слоя (док 180 §3: билдер port-struct в образе отсутствует).
- Same-version SKU-пары CX-5 дают идентичный дифф в двух версиях
  (реплика) при нулевом пересечении с версионным шумом — метод
  воспроизводим; для новых версий достаточно P2-реплики + same-PSID
  контроля.

## 4. Дополнение арки D (2026-11-13): маска IB-скоростей — источник и бит-карта (T2)

> Источник: цикл serdes-arc-d task-02 (журнал
> `docs/superpowers/journal/2026-11-12-serdes-arc-d-task-02.md`;
> инструмент `scripts/probes/serdes-arc-d/ibmask_hunt.py`); live-исходы —
> отчёт `docs/superpowers/reports/serdes-arc-d.md`, канон поля — док 180 §9.

Поле отсутствует в SKU-диффах (маска не SKU-фича) — источник в коде:

- **Сайт**: MAIN_CODE, apply_stamping_ib-гомолог — immediate-слово
  `fcb1c083` (`shr r17,r5,0x18`) @dc **0x1f2054** (1912-GCA; raw
  0x37f258) / @dc **0x1f1f00** (1900-GCA; raw 0x37e0f0); форс-путь
  стока — константа `0011001f` @dc 0x1f208c (1912). Слова-замены:
  L3 = `0011001f` (addi r17,zero,0x1f), L4 = `0011003f`.
- **Force-константа 0011001f инвариантна** по всем билдам/PSID
  cx4/cx4lx/cx5 корпуса арки A (EDR-эра, кросс-поколенчески) — маска не
  дифференцируется ни по SKU, ни по поколению.
- **Бит-карта**: bit0 SDR, bit1 DDR, bit2 QDR, bit3 FDR10, bit4 FDR,
  bit5 0x20 EDR. Провениенс-разделение: **биты 0-4 — live-корроборированы**
  (readback Enabled 0x1f на прожжённой 0011001f; партнёр CX-4 0x3f
  live), **bit5 — convention-derived** (C12-изоморф 8008-Rosetta),
  live не наблюдается (постфильтр FW снимает 0x20: 0x3f → effective
  0x1f).
