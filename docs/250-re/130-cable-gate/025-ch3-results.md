## 1. Стена снята сменой билда

Фаза A (95 §3, `010-wall.md`) закончилась стеной; глава 3 арки (план
`docs/superpowers/plans/2026-10-08-transceiver-ib-ch3-ghidra-gate.md`)
обошла её ретаргетом на 16.35.4030 и закрыла гейт. На 4030 (в отличие от
8008-стены фазы A) строки гейта адресованы инлайн — addi+addi.hi-пары →
dc+0x800000 (**7211 пар**, task-04), data-base-регистр не нужен, RE чисто
статический; boot-инъекция не понадобилась для RE, но пригодилась как
CR-дамп RAM (c9a2). **RETEST (owner):** природа 8008-стены не подтверждена
повторно — есть вероятность, что на 8008 что-то пошло не так в фазе A (а не
«стена» билда); ретест-разбор — §7 (стена снята как артефакт метода,
2026-10-15).

## 2. Гейт (MAIN_CODE 16.35.4030, все dc)

Цепочка (детали + live-доказательства — `002-transceiver-ib-gate.md` §1–§2):
классификация fn 0x28f880 (запись типа 0x940c+type·0x70; IB-терм =
`[+0x44]>>24`) → `set_pm_speed_and_width` fn 0x25a5b0 → IB-ветка
`apply_stamping_ib` fn 0x25a2f0: `speed_enabled = requested & module_term
(load dc 0x25a3e8-ec) & ~postfilter(0x25a560-7c)`; 0 → event 45 (6→0),
серды спят, порт Disable навсегда (Polling не наступает); ≠0 → `open_pport`
fn 0x258ef0 → nego → Link_Up.

## 3. Теорема SFP28

IB-поля в EEPROM SFP28/SFP+ нет ни в одном смещении (тип модуля определяет
порт; шаблон SFP28 читает только Eth-поля) → модульный терм = 0 конструктивно,
перекодировка невозможна в принципе; отвергается любой SFP28-модуль,
включая genuine Mellanox (`005-chain.md` §4). Единственные рычаги — FW-патч
или QSFP-гнездо. Полная форма — `../100-formats/070-transceiver-eeprom.md` §3.

## 4. Патчи (live-вердикты)

| Кандидат | Сайт | Вердикт |
|---|---|---|
| C4 | dc 0xa348 (форс cap-геттера) | опровергнут |
| C7 | fn 0x1eb7dc («зеркало B») | опровергнут |
| C8 | dc 0x1edae4 (статус-слово sink) | опровергнут (sink не вызывается) |
| C6 | dc 0x254168/0x2541bc (SCS-фидеры) | подтверждён, но только SCS-дисплей |
| **C12** | **dc 0x25a3ec: `fcb1c083`→`0011001f`** | **гейт снят** (замена модульного терма константой; IB-путь only) |

Минимальный образ = graft + C12 (c12min): линк и фабрика без остальных
патчей; SCS при этом честный 0x0 у EN-модулей.

## 5. Live-итог

- 01:00.1↔03:00.1 SFP28↔SFP28 **Active/LinkUp IB-FDR 1x** (обе карты
  graft+C12; width-гейта нет, 1x согласовался) + полная IB-подсеть (opensm на
  bazzite, lids 3/7, ibhosts 2×CA).
- QSFP-путь доказан отдельно: byte-164 каузальный A/B (0x07↔0x0f → SCS
  0x0f↔0x1f) + IB-FDR 4X ↔ EDR-карта (task-11; легальный путь без FW-патча —
  `docs/850-howto/110-transceiver-programming.md`).

## 6. Метод-бонусы и открытое

- iTrace-наблюдение гейта в переходной фазе (маска `0x4000C40`;
  `../100-formats/065-fw-trace.md`; c10); 2×2-матрица легальных углов — в
  steady-state мёртвый угол неотличим от рабочих (`0x3498=0x11` везде, PM
  молчит на Active-линках; расхождение — только в момент штамповки;
  `002-transceiver-ib-gate.md` §5); transition-capture (PAOS-админ-цикл на
  4030 молча игнорируется, окно = re-plug); CR-дамп инъекцией (c9a2):
  cap-глобалы ПОЛНЫЕ даже на SFP28-карте (`0x34cc=0x07270303`,
  `0x34ce=0x30c02055` FDR10+FDR+EDR) — IB выключен логически, одним словом.
- **Открытое (→ TODO.md):** EDR-лимитер (без C7 ELS-маска всё равно 0x17 —
  лимитер в настоящем compos; cap-биты в 0x34ce уже есть); честное снятие
  opcode 25 (после C12 opcode 26 ушёл сам; 25 — косметика на живых линках);
  актуализация арки-спеки (владелец: post-plan).
- **Образы/откаты** (обе карты остаются на VPI — решение владельца):
  bazzite 03:00.x — c12min активно; сервер 01:00.x — флеш = c12min
  (активация отложена до естественного ребута); лестницы ri-бэкапов —
  приложение `../100-formats/070-transceiver-eeprom.md`.

## 7. Ретест 8008-стены (2026-10-15, офлайн; стена — артефакт метода)

Журнал: `docs/superpowers/journal/2026-10-15-8008-wall-retest.md` (полные
таблицы, дизасм-доказательства, разбор «лог-каталога»). Выжимка:

- **Base = 0x800000, и он в образе.** ITOC MAIN_CODE (mlxfwutil RAM map):
  `load=0x00800000 jump=0x0081d5b0`; семантика по mstflint
  (`cibfw_layouts.h`): `param0` = load address, `flash_addr` (0x1c748) =
  офсет во flash. Фаза A перепутала их. Entry-паттерн на dc 0x1d5b0
  (`call sp_init; st.d!; call main; jump self`) — как у 4030.
- **Пары:** де-фрейм (clcrc=1, 0 ошибок CRC / 58918 линий) → dc-блоб
  0x398988 B; полный скан addi+addi.hi (RS(hi)==RD(lo), окно ≤3): **8486
  пар, 8463 в runtime-диапазоне секции, 6455 exact-start строк** — консенсус
  пар подтверждает base; «data-base регистр» не нужен. Гейт-кластер (dc):
  HighBER 0x385959 / FDR10 0x3859d8 / CS 0x385a0c / NoIssue 0x385a24;
  NoIssue2 0x34a3ce; сайты: HighBER 0x2519e8 (fn 0x251818, пишет
  monitor_opcode=26+строку), CS 0x2521e0 (fn 0x25201c, PDDR-troub mapper,
  dispatch @0xb93ddc), FDR10 0x251f30/0x254a78, NoIssue
  0x2547cc/0x2547f0/0x254a84.
- **Цепочка 8008 (изоморф канону 4030):** классификация **fn 0x28ffe0**
  (запись **0x4a020+type·0x380**, 0xdc B; 4030: 0x28f880/0x940c+type·0x70) →
  `set_pm_speed_and_width` **fn 0x25ad1c** (ETH/IB-ветки; ≈4030 0x25a5b0) →
  IB-ветка `apply_stamping_ib` **fn 0x25aa5c** (≈4030 0x25a2f0; единственный
  вызов @0x25b458): `speed_enabled = requested & (module_term|0xffffff00) &
  ~postfilter` (AND @0x25ac0c-18; пост-фильтр @0x25ac6c-e8, окно
  0x7b830+local·0x2800); 0 → нотификатор 0x29cf3c + флаги → PM FSM (вызов
  set_pm @0x25de40) пропускает serdes 0x257d50 + open_pport 0x25965c (≈4030
  0x258ef0).
- **C12-аналог (документирован, НЕ собирался):** модульный терм =
  `ld.d r5,r1,0x4c` + `shr r17,r5,0x18` @ **dc 0x25ab54-58**; сайт
  one-word-замены — **dc 0x25ab58 / raw 0x28060c / file 0x29cd54**, старое
  слово **`fcb1c083`**, аналог замены `0011001f` (`addi r17,zero,0x1f`;
  само-аттестован стоковым форс-путём @dc 0x25ab90 — слово `0011001f` уже в
  стоке). Дословный перенос C12 4030 (`002-transceiver-ib-gate.md` §3).
- **«Лог-каталог» фазы A закрыт:** серия raw 0x3c5fec..0x3c6550 = dc
  0x38d2c0..0x38d7d4 — однородные `0x0094/0x0093|lo16` слова (декод:
  `addi r20/r19,r4,imm`); на начала строк в raw попадают 3/181 entries
  (флагманы re2 — промахи внутрь строки), в dc линейной базы не существует
  (132 кандидата) — это не каталог и не подтверждение «базы 0x3b0000».
