## 2. Уточнения диспетчера и форматов

- Диспетчер `sign` — `subcommands.cpp:1792-1848`: дайджест-ветка (без ключей) —
  `:1841` → `FwInsertSHA256`; с ключом — signer `MlxSignRSAViaOpenssl` (`:1821`),
  SHA-тип по длине ключа: 0x100 (RSA-2048) → SHA-256, 0x200 (RSA-4096) →
  SHA-512 (`mlxsign_signer_interface.cpp:44-70`).
- `sign` с RSA-4096 перед подписью обнуляет младшую секцию:
  `Fs3MemSetSignature(0xA0)` → 0x00 (`fs3_ops.cpp:3284-3290`; если секции нет —
  тихий пропуск); зеркально SHA-256-ключ обнулил бы `0xA3`. Подпись → `0xA3`
  через `InsertSecureFWSignature` (`fs3_ops.cpp:4595-4643`).
- `set_public_keys <file>`: файл обязан быть **ровно размером секции**
  (для `0xA4` — 4352B), сырая BE-копия без TOCPUn (`GetSectData`, memcpy);
  тип секции — по `auth_type` **первого слота** (0x3 → `0xA1`, 0x4 → `0xA4`;
  `CheckPublicKeysFile` `fs3_ops.cpp:3453-3504`); на образах без `0xA6`
  (CX-5 OEM) трогает только `0xA4` (`fs4_ops.cpp:4980-5020`); после замены —
  `INSERT_SHA_IF_NEEDS` авто-пересчёт `0xA0`-деста для не-SIGNED_FW образов
  (`fs3_ops.h:83-101`).
- Порядок сборки self-signed: **сначала** `set_public_keys`, **потом** `sign`
  — вольт `0xA4` входит в подписываемые данные `0xA3` (`010-payload.md`).
- `rsa_sign` на устройстве читает образный вольт: `GetRSAPublicKey`
  (`fs4_ops.cpp:4735-4761`, первый `fw_en==1` слот; вызов
  `subcommands.cpp:9025`).

## 3. Ограничения

Подпись для устройства (не файла) запрещена: `SignForSecureBoot` /
`SignForFwUpdate` возвращают `not allowed for devices` при `is_flash()`
(`fs4_ops.cpp:5185`, `fs3_ops.cpp:3267/3272-3275`); `FwSetPublicKeys` отказывает
flash-хэндлу так же (`fs3_ops.cpp:3515-3518`). Обе операции — офлайн-правки
образа (журнал `2026-10-29-securefw-gates-task-01` §2.1/§5).
