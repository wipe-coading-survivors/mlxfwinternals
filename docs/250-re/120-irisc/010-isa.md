## 1. Установленные семантики (база, 2026-10-05)

Opcodes/формы — по каноническому декодеру `scripts/irisc/irisc_dis.py`
(`dis(w, off)`, 43-142; чтение файла — строка 152). Семантики —
live/алгоритмически верифицированы:

| факт | семантика | источник |
|---|---|---|
| set0-3 | вставка 16-битных halfwords, hw0 = MSB (set0 → биты 63..48, set1 → 47..32, set2 → 31..16, set3 → 15..0) | i2b §5:51-56, 114-115; slaspec 223-237 |
| lw.r | `lw.r rd,rA,rB = mem32[rA+rB]` — симметричное сложение | i2b §5:116; slaspec 395 |
| st.d! | store в [rs+off], затем rs += off (post-inc; push стека −0x18, copy +4) | i2b §5:117; slaspec 327-329 |
| shrh | `shrh rd,rs,n = (rs>>32)>>n` (shr старшей половины) | i2b §3/§5; roadmap 110-114 |
| addi.hi | `addi.hi rd,rs,imm = rs + (imm<<16)` | i2b §2:20-23, §5:114 |
| cc0 / cc3 | cc0 = eq/zero (идиом b.f cc0 = «while ≠» loop); cc3 = unsigned strictly-greater (дискриминирован на FIPS-edge fill=55: «≥» ломает, «>» воспроизводит) | i2b §5:118-121; slaspec cc-таблица 165-181 |
| cmp.w (op 0x38) → cc0a | sel=0x00 (eq32) пишет cc0a-latch с 32-битной обрезкой: `CMPRES = eq(trunc32(rs), trunc32(rt))`; live (fuzz-2 P2: r5=1<<32 vs rt=zero → taken) + статика (26/28 сайтов: b.t/b.f cc=0x0a в +1..3 словах) | task-08 §1-4; roadmap 145-151 |
| cc=0x0a consumer | `b.t/b.f.cmpres` — чтение compare-latch: второй механизм условий, независимый от N/Z/C/V; селектора 0x0a нет в cc-таблице синдиката | roadmap 100-101; slaspec 173; task-08 §5 |
| CMPRES register | модель регистра `offset=0x81008 size=1` (не заявленный архитектурный CSR; стиль согласован с Z64..V32 @0x81000) | slaspec 57-59; task-08 §5 |
| 0x36 ≠ compare | наша форма 0x36 НЕ ставит вход cc0a (fuzz-2 P1/P3 not-taken при прошедших контролях C1/C2); модели H-A/H-B/polarity/G/sel-ось/операнды мертвы *(уточнено fuzz-3: 0x36 кормит cc0a — predicate-compare; см. §3)* | task-08 §1-3; roadmap 145-151 |
| rotate idiom | `shl64.i rd,rs,s` + `shr rt,rs,32−s` + `or` = (x<<s)\|(x>>(32−s)) | i2b §5:109-110 |
| call/ret | hardware link stack: call (op 0x25, bit24=0) push, ret.d/ret.r (funct 0x2d/0x25) pop | i2b §5:122-125; slaspec 342, 397-402 |
| branch cc selector | cc = биты (16,20) branch-слова | i2b §5:118; irisc_dis.py:124-125; slaspec `cmpop=(16,20)` |

Плюс (i2b §5:110-117): add/addi/subsi — mod-2^32 регистры; `or r21,r2,r2`
(or того же регистра) = move; `r30 = addi −1` = 0xffffffff (используется как
~e); entry-идиом `csr.r r3,csr0xbc`; K-таблица `@0x3940a8` — 64 BE u32, 64/64
exact match со стандартными SHA-256 K-константами (i2b:9); SHA-256 suite:
transform `@0x2b13b0` + init/update/final (roadmap 110-112).
Здесь roadmap = `docs/010-roadmap/100-irisc.md` (фаза I).

## 2. Аддендум 2026-10-25 (WP-1/WP-2: статический grind + C3)

Установленные факты (отчёт `docs/superpowers/reports/irisc-isa-static-grind.md`
— консолидирующий; журналы `2026-10-25-irisc-isa-i2-bitops-grind.md`,
`2026-10-25-irisc-isa-wp2-c3-check.md`):

1. **C3 (критерий ISA-RE спеки) закрыт** — cc0a-consumer + cmp.w op38
   (`4f4f7b3`) достаточно для декомпиляции без unkBrCond-дыр: 0 дыр на
   9/9 core/0x36-плотных функциях (F_A @0x091534, F_C @0x0afd20, QUERY
   @0x0e4250, FN_A @0x18d964, T1.1-диспетчеры 0x1697cc/0x1617c4, 0x23e5d4,
   0x0d9c20, 0x154de0); на upstream-спеке — 15+2 дыры и 6/9 NO-FUNCTION.
   0x36-продюсер рендерится void-call `UnkOp(0x36,…)` без потери структуры.
   op38 cmpop=0 (биты 16..20 = rd-поле): 25/32 сайтов → cmp.w; rd≠0 (7) —
   value-form, sel≠0 open.
2. **0x33/0x34/0x36 — поздние опкоды** (census code-mask): 16.19.1200:
   0x33=231, 0x34=**0**, 0x36=2 против 4030: 2115/1492/3774. 0x0d — старый
   и стабильный (1619: 4842 > 4030: 3393). Следствие: 16.19.1200 —
   Rosetta-источник для функций, общих с 4030 (старый компилятор — те же
   операции известными опами).
3. **Первая кросс-версионно-доказанная семантика bit-op**: `0x34 f5=2 =
   rs & ~(1<<idx)` — Rosetta-пара dc 0x08c124 (4030) ↔ 0x057514 (1619),
   инструкция-точное выравнивание (score 31/32) ⟺ `and ~2`. *(Семантика
   слота уточнена isa-max-B: маска 0x00000006, deposit 0 — P-формула,
   см. §6; Rosetta-сайт сохранён.)*
4. **lo11-декомпозиция 0x33/0x34**: flag[10] | idx[9:5] | f5[4:0]; классы
   (f5,idx,flag) кросс-версионно идентичны (4030/8008/14.32/CX6Dx) — одна
   система кодирования. 0x33 f5=1: idx∈0..31 (бит-позиции); 0x34 f5=8:
   idx∈{0,8,16,24} (байты).
5. **Кластеры** (для навигации RE): 0x34-гигант 0x3156c4..0x319bb0 (443
   сайта) = ESW/MPFS/LLDP + ASN.1; 0x0d+0x33 общий кластер
   0x327xxx–0x32b000 = QPC/SRQ reformat (mlx5_ifc.h — источник точных ширин
   полей для гипотез); 0x33-топ 0x296d2c..0x2996cc (155) =
   capability/dispatch-маршалинг.

Гипотезы того цикла (H-0d-A, H-0c-ANDN, H-34-dep, H-33-bit/minmax) —
разрешены позднее (§3–§6: мёржи либо live-опровержения).

## 4. Аддендум 2026-10-30 (cx6dx-introspection task-03): errata cc2/lt32

Errata закрыта (правило 2-подтверждений выполнено), slaspec исправлена:

- **cc2/lt32 инвертирована в slaspec (было)**: формула
  `Z32==0 && N32==0` после `subs/subsi` фактически даёт RS>RT
  (signed, «результат > 0»), а не lt32. Фактическая семантика
  (name-faithful): **RS < RT (signed) = N32==1**. Исправлено в
  `scripts/irisc/iRISC.slaspec` (cc2-only; рендер/мнемоника не
  меняются, тесты формулы не парсят).
- Подтверждение 1 (cx6dx-securefw task-04): рег-гейт MFPA/MFBA/MFBE
  cx6dx-main03:0x18e714 (`subs` 0x902f−reg, `b.f.0x2` @0x18e76c),
  live-якорь — MCC-маршрутизация (0x9062/0x9063 обязаны диспетчеризоваться,
  live rb/verify работают).
- Подтверждение 2 (cx6dx-introspection task-03, независимое): диспетчер
  внутренних команд cx6dx-main03:0x167650 (`subs` 0x9000−cmd,
  `b.f.0x2` @0x167670): команды 0x8404 (verify-cmd → 0x404d08) и
  0x8405 (компаратор burn-verify → 0x404ad4) достигаются только при
  name-faithful чтении; live-якорь — burn-verify на живой карте
  (REJECT 0x5, docs/250-re/110-signing/055-cx6dx-signing.md). Другой
  сайт/механизм/константа — независимость соблюдена.
- **Уточнение: cc4/ult32 в slaspec корректна** — `Z32==0 && C32==0`
  при C32 = RT<RS (subs) / RS>simm (subsi) ≡ «RS <u RT && RS≠RT» =
  name-faithful. Заголовок первого подтверждения «lt32/ult32
  инвертированы» сужен до lt32 (свежий cc4-сайт cx6dx-main03:0x22454 —
