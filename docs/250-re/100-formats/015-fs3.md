# 015. FS3: бут-заголовок и ITOC-заголовок

> Источник: mstflint `mlxfwops/lib/fs3_ops.{h,cpp}`, `tools_layouts/cibfw_layouts.{h,c}`;
> эмпирика — 6 образов CX-4/CX-4Lx `refs/fw/` (журнал 2026-09-15, пробник
> `scripts/probes/toc_probe.py`). Чипы: CX-4, CX-4Lx (заголовок CNTX
> использует и CX-2-образ — детекция в `005-detect.md`).
> ITOC-запись и типы секций — `020-fs3-sections.md`; CRC — `025-crc.md`.

## 1. Бут-заголовок (первые 0x38 байт)

- 16B — CNTX-маг; далее служебные поля.
- **Version word @ 0x24** (DW9): для BCA `03 17 01 01` (BE u32
  `0x03170101`). Разбор:
  - byte 0x24 = `image_format_version` = **3** (детекция, `005-detect.md`);
  - byte 0x25 = bits 16-23 (LSB-first `EXTRACT`, `bit_slice.h:39-40`) =
    **log2_chunk_size = 0x17 = 23** (`fs3_ops.cpp:804-805`,
    `fs3_ops.h:351 FS3_LOG2_CHUNK_SIZE_DW_OFFSET 0x9`);
  - bytes 0x26-0x27 = binVer major.minor = **1.1**
    (`fs3_ops.cpp:807-808`, проверка `CheckBinVersion`).
- За бут-заголовком идёт BOOT2, затем **ITOC**, выровненный по
  сектору `FS3_DEFAULT_SECTOR_SIZE = 0x1000`; поиск — сканирование
  вперёд по 0x1000 до валидной сигнатуры ITOC
  (`mlxfwops/lib/fs3_ops.h`, `fs3_ops.cpp:835-862`).

Механика сканера (журнал 2026-09-15, 6 образов): старт
`image_start + FS3_BOOT_START + boot2Size`, округлён вверх по 0x1000,
шаг 0x1000 до `get_effective_size()`; `CheckTocSignature` проверяет все
4 слова (`fs3_ops.h:221-224`); сигнатура + битый CRC → hard-fail, нет
сигнатуры → skip. 16-байтная сигнатура — ровно 1 вхождение @0x2000 во всех
6, ложных хитов нет.

Эмпирика: во всех трёх CX-4Lx/CX-4 образах ITOC @ **0x2000**.

## 2. ITOC-заголовок (32 байта)

Константы: `fs3_ops.h:221-224` (`ITOC_ASCII 0x49544f43`,
`TOC_RAND1 0x04081516`, `TOC_RAND2 0x2342cafa`, `TOC_RAND3 0xbacafe00`),
массив `_itocSignature` — `fs3_ops.cpp:78`.

| Смещение | Поле | Значение/примечание |
|---|---|---|
| 0x00-0x03 | signature0 | `49 54 4F 43` ("ITOC") |
| 0x04-0x07 | signature1 | `04 08 15 16` |
| 0x08-0x0B | signature2 | `23 42 CA FA` |
| 0x0C-0x0F | signature3 | `BA CA FE 00` |
| 0x10-0x12 | reserved | 0 |
| 0x13 | version (bit 152) | 1 (во всех наших образах) |
| 0x14-0x1D | reserved | 0 |
| 0x1E-0x1F | header CRC (bit 240) | CRC-16 по первым 28 байтам |

(Структура `cibfw_itoc_header` — `tools_layouts/cibfw_layouts.h:500`,
unpack — `cibfw_layouts.c:1090-1091`, version читается с bit 152,
MSB-first → байт 0x13. Комментарий в `.h` (`0x10.0-0x10.7`) —
устаревший, не соответствует unpack.)

## Приложение: A/B-слоты 16MiB (эмпирика 6 образов, журнал 2026-09-15 R5)

Флеш = 2×8MiB (log2_chunk=0x17=23 = размер слота).

- image start: 0x0 (A) или 0x800000 (B); `FindAllImageStart`
  (`fw_ops.cpp:409`) ищет CNTX-magic в 11 позициях (`fw_ops.cpp:380`,
  вкл. 0x800000); burn чередует слоты (`getNewImageStartAddress`:
  A→B, B→A; non-failsafe+ocr→0x0).
- cont2phys (`flint_io.h:211`): слот A — identity, слот B — +0x800000.
- **Адреса:** rel=1 (FW) — континуум, в слоте B сдвиг +0x800000; rel=0
  (device-data) — **абсолютные** (без +base, всегда 0xFA0000–0xFF8140).
  Вендорные .bin (слот A, base=0) — без сдвига. `detect_format` 16MiB FS3:
  проверять CNTX в обоих слотах; slot B — FW-секции +base, device-data — без.
