# 025. CRC-16 образов (общий для FS2/FS3/FS4)

> Источник: mstflint `mft_utils/crc16.{h,cpp}` (класс `Crc16`); эквиваленты
> — `refs/src/BeTeP-STH_mft-scripts/fs2_update_ini.py`,
> `refs/src/Mellanox-ConnectX-5-PCIe-Gen-4-Enablement/cx5_gen4_enable.py`.
> Применения: `010-fs2.md`, `015-fs3.md`, `020-fs3-sections.md`.

## 1. Алгоритм mstflint

`mft_utils/crc16.cpp` (класс `Crc16`; init `0xFFFF` — `crc16.h:40
clear()`). Алгоритм — битовый цикл по байтам файла в натуральном
порядке, MSB-first (по BE u32 словам, `crc16.cpp:34-52`):

```c
crc = 0xFFFF
for each bit b of data (MSB-first, байты в порядке файла):
    top = crc & 0x8000
    crc = ((crc << 1) | b) & 0xFFFF
    if (top) crc ^= 0x100B
/* финализация — ещё 16 нулевых бит тем же циклом (crc16.cpp:54-69) */
for i in 0..15:
    top = crc & 0x8000
    crc = (crc << 1) & 0xFFFF
    if (top) crc ^= 0x100B
crc ^= 0xFFFF
```

## 2. Это НЕ стандартный параметризуемый CRC-16

Внутренний цикл нестандартный: входной бит OR-ится в LSB, а полином
применяется по старшему биту регистра **до** сдвига; в стандартной
byte-wise/табличной реализации (poly 0x100B, init 0xFFFF, MSB-first, без
рефлексии, xorout 0xFFFF) бит XOR-ится в старшую позицию (эквивалентно —
проверка `top ^ b`). Две формы совпадают при init=0 и расходятся при
реальном init=0xFFFF (проверено: 20/20 случайных выборок, 4–1000 байт).
Пример — ITOC-заголовок 28 байта, MCX4131A BCA: стандартная форма
даёт `0x51d8`, mstflint — `0x6a70` (хранящееся в образе значение;
верифицировано по скомпилированному `Crc16`). Реализация «по
параметрам» из стандартных библиотек/таблиц даст неверный CRC.

## 4. Применение

- данные секции → `section_crc` (0x0000 при `no_crc=1`);
- первые 28 байт ITOC-записи / ITOC-заголовка → entry/header CRC;
- FS2: CRC-16 целого образа @ `0x22` (`010-fs2.md`).

## 5. Реализации в mlxfwutil

- `mlxfwutil.crc16_mlx` (`mlxfwutil.py:80`) — табличный эквивалент цикла
  mstflint (init 0xFFFF, xorout 0xFFFF); используется для всех
  section/entry/header CRC и FS2-образа.
- `mlxfwutil.calc_hw_crc` (`mlxfwutil.py:119`) — **другой** алгоритм:
  HW-CRC записей HW-указателей FS4 (полином 0xD008 reflected —
  crc16table2 из `mft_utils/calc_hw_crc.c`; инверсия первых 2 байт,
  байто-своп результата). mstflint принимает CRC HW-ptr entry, если он
  = SW-CRC (CRC-16 по DW ptr) **или** = HW-CRC (`calc_hw_crc` по 6 байтам
  entry, `mft_utils/calc_hw_crc.c:56-71`; выбор `fs4_ops.cpp:306-325`).
  Не путать с CRC-16 образов.

## 6. Порядок пересчёта при правке секции (из 90 §5)

При правке данных секции порядок обязателен: сначала `sec_crc` (байты
0x1A-0x1B записи — входят в первые 28 байт, покрываемые entry-CRC), затем
`entry_crc` по уже обновлённой записи (карта байтов — `020-fs3-sections.md`
§1; инструментальную матрицу см. `docs/550-poc/100-mlxfwutil/020-patch-matrix.md`
§1). Эмпирическая привязка (Dell `16_27_6120`, секция 0x12): `sec_crc` по
**сырым** байтам секции — stored `0x319d` == calc (по word-swapped —
`0xd802`, мисматч); `entry_crc` по `entry[:28]` — stored `0x3c1a` == calc.
DTOC при правке FW-секций не затрагивается (DTOC — только device-данные,
`030-fs4.md` §3).
