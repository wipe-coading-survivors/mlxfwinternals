## 1. Layout: grid 32 + 16×176 (CX-4/4Lx/CX-5)

11392 B = 2848 BE32-слов = **заголовок 32 слова + 16 таблиц по 176 слов**
(0x2c0 B). Автокорреляция BE32 даёт пик lag=176 (eq-доля 0.488); гипотеза
сетки подтверждена парными совпадениями таблиц (task-03 §0, первичная
census-улика). Заголовок — таймауты/маски (0x1404, 0xf424=62500, 0xfa00,
…), не rate-магия.

md5 по семьям (SKU-инвариантен внутри версии: 1900≡1912, 8008≡1012≡4030):

| семья | md5 0x0B | размер | layout |
|---|---|---|---|
| cx4 12.28 + cx4lx 14.32 | `53d67169…` | 11392 | grid 32+16×176 |
| cx5 16.35 | `cfc43622…` | 11392 | тот же layout, контент отличается (1060 B от cx4) |
| cx5 16.19 (старая ветка) | `dcb6ed3d…` | 11392 | тот же layout; 727 B от cx4, 577 B от 16.35 |
| cx6 / cx6dx / cx6lx | `a5058431…` | **1280** | single zero table (320×0), grid none — §5 |

Grid найден во ВСЕХ CX-4/4Lx/CX-5 образах, включая 16.19 — структура
инвариантна CX-4↔CX-5, дрейфует только контент. Структурный отпечаток
(17 таблиц, классы, sub-strides {2,5}) одинаков во всех шести.

## 2. Классы энтропии таблиц

Эвристическая классификация (пороги зафиксированы до тестов; классы
«looking» — БЕЗ семантической валидации, см. докстринг
`phyuc_consts.py`): **zero** (≥0.9 нулей) > **counter-like** (stride-1
монотонный забег ≥6 мелких дельт) > **timing-looking** (ступенчатый
рамп в колонке stride 2, plateau ≥1.5) > **analog-looking**
(distinct-ratio <0.6, top-frac ≥0.10) > **mixed**. Профили: t0 —
монотонный спад 0x1000→0x2af + тап-зона 0x8080; t1/t4 — stride-2 пары с
убывающим рампом («timing»); t7..t14 — коэф-пары {0x6axxx, 0x56a0x}
(аналог C4-топов 0x56a0/0x6720/0x3fc0); t15 — нулевая.

## 3. Generation-invariant и дрейфующие таблицы

Per-table md5 (task-03 §5, первичная):

- **t00 (заголовок), t07, t16 (zero) побайтово идентичны во всех
  четырёх ветках** (cx4/cx4lx/16.35/16.19) — generation-invariant якоря;
- t01..t06 дрейфуют per-ASIC (дифф cx4↔cx5 = ровно 1060 B — совпадает с
  C4 §6);
- t08..t15 (коэф-таблицы: 4+3+1+1 копий): cx4 ≡ 16.35, но 16.19
  отличается — ревизия коэф-слоя между 16.19 и 16.35.

Гипотеза «16 таблиц = per-lane (16 ланов)» — **ослаблена, не
опровергнута** (первичная, структура копий): 8 из 16 таблиц побайтово
идентичны внутри образа (t08–t11 ×4, t12–t14 ×3 + t07 квази-копия), а
per-lane таблицы обязаны различаться (lane-калибровка). Кандидат —
per-режим/per-фаза (rate/eq-профили); точная семантика не установлена
(дискриминатор: сверка с 0x08 schedule-таблицей или live-проба).

## 4. Не адресная, не индексная (связь с 0x0A/0x0C)

- Структурных ссылок на банки 0x0A/0x0C нет (C4 §6): BE16-хиты
  банк-констант (0x09cc×24, 0x5814×6) локализованы в повторяющихся
  коэф-парах `0x000509cc 0x00085819` ×12 — числовые совпадения, не
  (bank,addr)-таблица.
- **index_alignment = 0 matches на всех 10 образах** (task-03, первичная):
  ни одно не-адресное поле слотов 0x0A (write.a/read.a/op2000.c/op8520.c/
  op3000.cd/lane.c) не индексирует таблицы при порогах coverage≥0.5 /
  density≥0.5 (зафиксированы до прогона).
- Вердикт: 0x0B = константы таймингов/калибровки движка (data для
  интерпретатора 0x0A/0x0C). Опровергнуто в пределах прямых
  интерпретаций; неявные/вычисляемые индексы — не найдено.

## 5. H-C-вердикт: per-rate вырезания в Lx нет

- **0x0B: cx4 ≡ cx4lx байт-в-байт (0 из 11392)** — на уровне констант
  вырезания 14-ГБод-конфигов в Lx-SKU нет (первичная, байтовый дифф).
- **0x0A: 1 различающийся байт из 39200** — слот 1351: `wr6165 p=27
  blk=3 reg=9cc addr=0x820 val 0→1` (первичная). Единственный
  µкод-дифференциал CX-4↔CX-4Lx; цель — в списке 9 точных общих
  (b,c)-пар 0x0A∩0x0C (пара (0x39cc, 0x0820), C4 §3) → дифференциальная
  мишень для арки D (гипотеза бит-гейта, не факт).
- Следствие: FDR-хендшейк Lx не объясняется отсутствием конфигов в
  0x0A/0x0B — консистентно кристалл-факту и H-B/H-D рамке
  (`docs/750-exp/180-serdes-provisioning.md` §6).

## 6. CX-6-gen: нулевой плейсхолдер 1280 B

0x0B всего CX-6-поколения (cx6 20.43 / cx6dx 22.47+22.50 / cx6lx 26.50,
md5 общий `a5058431…`) = 320 BE32-слов нулей — пустой плейсхолдер,
движок CX-6-gen константы в этой секции не хранит. Куда делись (task-03
§CX-6, проверено офлайн):

1. **Immediate-поля 0x0A/0x0C (write-d):** прямое значение low16
   CX-5-0x0B в d-множествах CX-6 — без обогащения над кросс-ген
   контролем (0.028/0.038 при базовой линии 0.027) — **не найдено**
   (вторичная негативная; перенос вычисляемых/расщеплённых значений
   проба не видит).
2. **Другая flash-секция:** маркерные коэф-значения (0x4052d/0x5a5ad/
   0x56a07/0x6bc80, 16..32 вхождения в CX-5-0x0B) — **0 вхождений** во
   всех секциях cx6/cx6dx (первичная по маркерам; экзотические
   перекодировки не исключены).
3. **ROM-движок:** остаточная гипотеза, open — ROM-dump owner-gated
   стадия 2 (`docs/850-howto/130-rom-dump.md`).
