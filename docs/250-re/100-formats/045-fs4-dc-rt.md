# 045. FS4: извлечение MAIN_CODE и dc↔rt-калибровка (CX-6Dx 22.50.1002)

> Источник: образ MCX623435AC (32 MiB, FS4, ITOC @0x5000), оффлайн-RE
> 2026-10-30; профиль чипа — `scripts/irisc/profiles/cx6dx.json`.
> Таблица размеров boot-секций — `040-fs4-domains.md` §4; clcrc-формат
> MAIN_CODE — `030-fs4.md` §4.

## 1. Извлечение MAIN_CODE

MAIN_CODE (0x03, clcrc=1): raw 0x5c9a00 → de-clcrc блоб **0x572780 B**
(89246 линий 64+4, ошибок line-CRC 0); iRISC-декодер покрывает 97.8%
known-op (контроль CX-5 тем же декодером 98.1%); строковый пул
[0x4d0000, 0x540000), после пула — кодовый остров (последний call-сайт
0x571abc).

Конвенции счёта размера: 89246 полных линий × 64 B данных = 0x572780
(здесь и в отчётах цикла); значение 0x572787 в таблице
`040-fs4-domains.md` §4 — та же секция в другой конвенции: включая
7-байтовый хвост после последней полной линии. **Инвариант парсера:**
учитывать частичный хвост последней линии.

## 2. Калибровка dc↔rt

**rt = dc + 0x21000000** (load base = ITOC param0 MAIN_CODE = 0x21000000 —
НЕ 0x800000, как у CX-5; entry param1 0x2102083c → dc 0x2083c).
Верифицирована 4 независимыми методами:

1. param0/param1 записи ITOC;
2. консенсус addi/addi.hi пар — 98.8% адресов в
   [0x21000000, 0x21000000+0x572780);
3. инлайн rt-пара на DER-якоре (rt 0x21565818 = dc 0x565818 + база);
4. rt-указательные таблицы данных в хвосте блоба (98 серий ≥8 слов).

Прочие load-базы (ITOC param0): 0x05→0x20710000, 0x04→0x20780000,
0x06→0x20742200, 0x02→0x20520000, 0x07→0x205f0000, 0x0d→0x20000000,
0x0e→0x30004000.

Отличие от CX-5: K512/H512 — таблицы данных в констант-блоке (у CX-5 —
imm-квадруплеты); H256-таблицы нет.
