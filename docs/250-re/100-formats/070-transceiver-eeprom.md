## 1. Главное

1. **IB-скорости трансивера живут в EEPROM только у QSFP-формата**
   (byte 164); у SFP28/SFP+ такого поля **нет вообще** — «включить IB
   в SFP28-модуле» перекодировкой невозможно в принципе (§3) — кроме
   SFP-модуля за QSA на QSFP-порту: порт выбирает карту по identifier
   модуля (byte 0), и SFP+ под QSFP28-личиной проходит сток-гейт (§3.1).
2. Гейт скорости IB в FW — одно место (штамповка скоростей
   `set_pm_speed_and_width → apply_stamping_ib`); модульный терм AND-ится
   с запрошенной маской, 0 на выходе = серды спят, порт навсегда Disable.
   Обход — C12 (одно слово FW заменяет модульный терм константой, порт
   уходит в Polling на ЛЮБОМ модуле) — карта гейта:
   `docs/250-re/130-cable-gate/002-transceiver-ib-gate.md`.
3. Перекодировка QSFP byte-164 — рабочий легальный путь для QSFP-портов
   (live-доказан FDR-линком; рецепт — `docs/850-howto/110-transceiver-programming`).
4. **QSA + SFP-рекод = сток-гейт пройден без C12** (2026-10-10):
   SFP-25G-SR (A0005) с byte 0=0x11 + byte 164=0x0f за QSA на стоковом
   41:00.1 → SCS 0x1f, **IB-FDR 1x Active/LinkUp, фабрика поднялась**
   (lid 2). Контроль: тот же модуль в SFP28-гнезде (c1:00.1) — SCS 0x0,
   теорема §3 в силе.

## 2. EEPROM-форматы: где живут IB-скорости

| | QSFP28 (SFF-8636) | SFP28/SFP+ (SFF-8432/8472) |
|---|---|---|
| Поле IB-скоростей | **byte 164** (биты SDR/DDR/QDR/FDR) | **нет ни в одном смещении** |
| Карта (что читает FW) | byte 164 + страничная модель | bytes 3/12 (Eth-compliance), 222-223 (BR), A2h — диагностика |
| Гейт на порту | по byte-164; **generic-медиа проходит на 4xSDR** (fallback на минимум — live: LR-оптика без IB-полей, 41:00.1 ↔ EDR-карта) | в SFP28-гнезде — отвергается ВСЁ (§3); в QSFP-гнезде — по identifier byte 0 (§3.1) |
| Перекодировка | работает (`850-howto/110`) | в SFP28-гнезде невозможна (§3); за QSA на QSFP-порту — возможна (§3.1) |

Live-доказательства QSFP-пути: каузальный A/B byte 164 `0x07↔0x0f` ↔
SCS `0x0f↔0x1f` бит-в-байт на стоке 41:00.1 (task-11, коммиты
c66d56e/52de590); перекодированный DAC → **IB-FDR 4X Active/LinkUp**
(a831ebb). 4xSDR-fallback на LR-оптике — журналы closeout (дуга «легальных»
матриц, task-12matrix/12transition). 2026-10-10: SFP-25G-SR (A0005)
перекодирован в QSFP28-личину (byte 0=0x11, byte 164=0x0f, CC_BASE 0x8a)
+ QSA на стоке 41:00.1 → SCS 0x1f, IB-FDR 1x Active/LinkUp, фабрика
поднялась; карта читает A0h 8472-модуля по SFF-8636-офсетам (Nominal 0.000,
PN/SN «N/A» — косметика; DDM жив — A2h читается как 8472).

## 3. Теорема SFP28: почему перекодировка невозможна

1. **Тип модуля определяет ПОРТ, не EEPROM.** Классификация
   (`fn 0x28f880`) выбирает шаблон по пер-портной таблице
   `word(0x5c107+port·0x4c0)&0x3f`; SFP28-гнездо → SFP28-шаблон.
   Вписать QSFP-раскладку в SFP28-EEPROM (хоть картой, хоть
   программатором) нельзя — тип не сменится, байты будут истолкованы
   по SFP28-карте.
2. **SFP28-шаблон не содержит источника IB-терма.** IB-вклад записи
   классификации (`0x940c+type·0x70`, терм = `record[+0x44]>>24`)
   рождается нулём конструктивно: шаблон читает только Eth-поля. Это не
   «бит защищён» — бита не существует ни в каком смещении.
3. Следствия (все подтверждены live): отвергается ЛЮБОЙ SFP28-модуль,
   включая genuine Mellanox (гл. 1; sweep task-10: 6/6 модулей SCS-дисплей
   0x1f через дисплей-патч C6, но порт Disable); единственные рычаги — FW
   (C12 — `130-cable-gate/002`) или смена гнезда (QSFP-карта).

### 3.1 Оговорка: QSFP-порт — карта по identifier модуля (2026-10-10)

Теорема — про SFP28-гнездо. На QSFP-порту выбор карты/шаблона зависит от
identifier модуля (byte 0): SFP-идентификатор (0x03) — отвергается (SCS 0x0,
opcode 26; дуга QSA+DAC, журнал `2026-10-04-transceiver-ib-bit-live.md`),
QSFP28-идентификатор (0x11) — SFF-8636-карта, гейт byte 164 активен. Отсюда:
SFP+-модуль за QSA может лицемерить QSFP28 — рекод byte 0=0x11 +
byte 164=0x0f → сток-гейт пройден (SCS 0x1f, IB-FDR 1x, фабрика; журнал
`2026-10-10-qsa-sfp-ib-recode.md`). Контроль: тот же модуль (ещё с
SFP-идентичностью) в SFP28-гнезде c1:00.1 — SCS 0x0 (гл. 1): SFP28-гнездо
SFP28-шаблон форсирует, теорема в силе.

**Аддендум 2026-10-17 (цикл персона+идентичность): механика дисплея.**
mstlink/ethtool-дисплей декодирует по **byte 0 модуля**, не по слоту:
A0005 (byte 0=0x11) в SFP28-слоте c1:00.0 показывается как QSFP28 с
8636-полями (Nominal 0.000 и т.д.), A0006 (byte 0=0x03) — как SFP28/SFP+
с 8472-полями (PN/SN видны). QSFP28-порт читает 256 Б нативно (live-факт
2026-10-17: A0005 за QSA в QSFP28-порту 81:00.0, карта `CARD_CX5_EDR100`
(MT28800, 16.35.4030 FS4) — Identifier QSFP28, SCS 0x100, вендорские поля
N/A до записи 8636-позиций — ожидаемо: позиции пусты). SCS-дисплей зависит
от карты/силикона, не от byte 164: тот же A0005 (byte 164=0x0f) за QSA —
41:00.1 (MT27800, 16.35.4030; 2026-10-10) → SCS 0x1f; 81:00.0 (MT28800,
16.35.4030; 2026-10-17) → SCS 0x100 — косметика, не гейт. Открытый вопрос
«отдаёт ли карта в SFP28-слоте полные 256 Б A0h» — **ЗАКРЫТ (да)**: после
заполнения 8636-позиций A0005 в c1:00.0 ПОКАЗЫВАЕТ вендорские поля (Vendor
Name OEM / Vendor PN SFP-25G-SR / Vendor SN A0005; до операции —
N/A); SCS 0x1f, Polling, Identifier QSFP28.

## 4. Постулаты / открытое

- QSA-рекод: EDR-бит (byte 164 = 0x1f) — открыто.
- Подъём линка 1-lane SFP28 под IB — hardware-вердикт (T10 «Г»): 1-lane
  SFP28-PHY не выставляет `csr0x1a4==2` для IB-AN (для EN — выставляет);
  4-lane QSFP28-PHY — выставляет. Детали — `130-cable-gate/002`.
- Включение EDR (cap-биты в 0x34ce уже есть) — предмет следующей главы.
- Персона A0006 (byte 0=0x03) не вшита — модуль-лок A0h: все 57
  password-кандидатов не сняли; follow-up (сервисный режим / другой
  программатор / замена модуля — решение владельца). Контроль byte 0=0x11
  в родном SFP28-гнезде — частично закрыт (§3.1: дисплей/256 Б; подъём
  линка — вне цикла, hardware-вердикт).
- Width для 1-лайнного гнезда — решено live: LinkUp **1x** (width-штамп
  0x3 = дефолтный енум, реальная ширина согласовалась 1x).
- Минимизация diff образа — закрыто: c12min = graft + C12 (дискриминатор
  live, приложение).
